RustDesk 是个开源的远程桌面，能白嫖官方服务器，也能自己搭。我一开始就是用官方的，
后来实在受不了，自己在腾讯云那台小机器上起了一套。

这篇写的就是那套东西怎么搭起来的。**先说明：这篇不是抄文档**——服务器是我自己装的，
下面的命令、端口、key、日志都是从那台机器上抓下来的。不确定的地方我会标出来。

## 先说人话：为什么要自建

官方的公共服务器有几个问题：

- **慢**。中继线路不在你家和公司之间，绕一圈。
- **要排队**。免费版连的人多，有时候半天握不上手。
- **心里没底**。你的连接信息（谁连谁）是过一遍别人服务器的。

自己搭一套，这两台机器之间的流量要么直连、要么走你自己的中继，延迟能低一截，
而且没有任何人插在中间。代价就是：你得有台有公网 IP 的机器。

**但如果你只有两三台机器、还都在同一个局域网，真的不用自建。** 
官方服务器够用，装完就能连。自建是给"经常跨网络连、又嫌卡"的人准备的。

## 需要什么

- **一台有公网 IP 的机器**（我就是那台腾讯云的小鸡）。配置要求不高，1 核 1G 都能跑。
- **会 Docker**。RustDesk 官方提供镜像，不用自己编译，省事。
- 域名？**可以不要**。直接用 IP 就行。想要 TLS 再说。

## 装：两个容器

RustDesk 自建服务器是两个角色的进程，官方拆成两个镜像：

| 容器 | 是谁 | 干什么 |
|---|---|---|
| `hbbs` | ID / 信令服务器 | 两个客户端靠它互相"看见"，交换彼此的地址和公钥 |
| `hbbr` | 中继服务器 | 双方打不通（都在 NAT 后面）时，流量从中继走 |

两个都要跑，缺一不可。**都得用 `--net=host`**，因为它们要监听一堆端口，
用默认的 bridge 网络那些端口全被关在容器里，外面连不进来。

我的机器上是这样起的（等价于我当时跑的命令）：

```bash
# 在你的服务器上执行
mkdir -p /opt/rustdesk

docker run -d --name hbbs \
  --restart unless-stopped \
  --net=host \
  -v /opt/rustdesk:/root \
  rustdesk/rustdesk-server \
  hbbs -r <你的公网IP或域名>:21117

docker run -d --name hbbr \
  --restart unless-stopped \
  --net=host \
  -v /opt/rustdesk:/root \
  rustdesk/rustdesk-server \
  hbbr
```

几个地方解释一下：

- `-v /opt/rustdesk:/root` —— 数据落在宿主机上。**这个目录千万别丢**，
  里面的 `id_ed25519` 就是服务器的身份私钥，重新生成的话所有客户端都要重配 key。
- `hbbs -r 你的IP:21117` —— 告诉 ID 服务器："中继在 21117"。**这个参数不写会出事**：
  客户端可能被指去用官方中继，等于白搭。
- 镜像默认就是跑 `hbbs`，后面那截 `hbbs -r ...` 是覆盖它的启动参数。

> 官方还有个 docker-compose 版本，效果一样。我用 `docker run` 只是因为当时顺手，
> compose 写起来更清爽，你用哪个都行。

## 端口：每个都有用

这是最容易糊的地方。我把它们列清楚（`ss -ltn` 在我机器上抓的实际监听）：

| 端口 | 协议 | 谁在听 | 干嘛的 |
|---|---|---|---|
| 21115 | TCP | hbbs | NAT 类型探测 |
| 21116 | TCP + **UDP** | hbbs | TCP 是 ID 注册/信令；**UDP 是心跳和打洞，这个最容易被忘** |
| 21117 | TCP | hbbr | 中继，流量真走这里 |
| 21118 | TCP | hbbs | 给网页客户端的 WebSocket |
| 21119 | TCP | hbbr | 给网页客户端的 WebSocket |

两个坑：

1. **21116 的 UDP 一定要放行。** 很多人只开了 TCP，结果能连上但打洞永远失败，
   什么都走中继，慢得要死。防火墙和云厂商的安全组**两处**都要开。
2. **21118/21119 如果你不用网页客户端，可以不开。** 我这边是因为安全组整段
   21115-21119 都放行了才留着。

### 只想给 tailnet 用？

RustDesk 这套的设计前提是"客户端从公网找得到你"，所以**默认它就是要开公网的**。
真要收紧，思路是：

- 如果你只在自己几台机器之间用，可以考虑**不开公网、只让客户端通过 tailnet 访问服务器**。
  但要注意 `hbbs` 是 `--net=host` 的，它会监听 `0.0.0.0`，所以"只绑 tailnet"
  得靠防火墙规则去卡（只放行 tailscale 网段），不是改个参数就行。**这点我没实测，标注一下。**
- 更实用的做法：把**别的**服务（比如 Tailscale 网络里才能访问的 Halo 博客、面板）
  都绑在 tailscale IP 上，只留 RustDesk 这对端口给公网。
  我服务器上就是这么分的 —— `ss -ltn` 里能看到 `100.x.y.z:8091` 这种绑定，
  明确只给 tailnet；RustDesk 则是 `*:21116`。

关于 Tailscale 那套怎么搭，我写在另一篇了：
[把自己几台机器连成一张网](/posts/self-host-tailscale/)。

## 客户端怎么填

装好客户端（Windows / macOS / 安卓 / iOS 都有）之后，找到「ID/中继服务器」这一栏，
很多版本藏在设置里，要点开"高级"或者长按才出来：

- **ID 服务器**：`你的IP`（端口默认 21116，不用写）
- **中继服务器**：留空也行，因为 `hbbs -r` 已经指定了；要写就写 `你的IP:21117`
- **Key**：这个必须填，见下面

**手机上尤其注意**：安卓/iOS 的界面更绕，通常在「设置 → 网络」或者长按主界面上的
ID 才会出现服务器配置。填完回去看一眼「就绪」状态，如果一直转圈就是没配上。

## Key 从哪来

第一次启动 `hbbs` 的时候，它会自己在数据目录里生成一对密钥。公钥就是你要填进客户端的 Key：

```bash
# 在你的服务器上执行（容器已跑起来的前提下）
cat /opt/rustdesk/id_ed25519.pub
```

输出是一串 base64，长这样（**这是我服务器的公钥，你那里当然不一样**）：

```
Grs7prZW8ToDsKCJRT6lJnRNQSEwBGppPY098Yv08Xo=
```

**客户端上就填这一串。** 填错了连不上，而且报错很含糊 —— 客户端就只会卡在那儿。

## 我踩到的两个坑

### 坑一：21116 被干扰，得换个口

这个比较特殊。我这边 21116 有时候会被网络中间设备干扰，表现是客户端时好时坏。
绕开的办法是把另一个已经放行的端口重定向过去 —— 我用了 21118：

```bash
# 在你的服务器上执行
iptables -t nat -A PREROUTING -p tcp --dport 21118 -j REDIRECT --to-ports 21116
iptables -t nat -A PREROUTING -p udp --dport 21118 -j REDIRECT --to-ports 21116
```

然后客户端 ID 服务器那里填 `你的IP:21118`。

**注意这只是我碰到的网络环境下的绕法，不是通用建议。** 你先用默认的 21116 试，
有问题再考虑这招。

### 坑二：忘了写 `-r`

我第一遍起容器的时候 `hbbs` 只写了 `hbbs`，没带 `-r`。结果是：
ID 能注册、也能看到对方的机器，但一连就"正在连接"转圈，最后超时。
后来翻 `hbbr` 的日志才发现根本没有中继请求进来 —— 因为压根没人知道中继在哪。

补上 `-r 你的IP:21117` 重启就正常了。

## 怎么确认它真的在工作

别只盯着客户端看，直接看服务器日志最快：

```bash
# 在你的服务器上执行
docker logs hbbr --tail 20
```

有中继在跑的时候，能看到这样的东西：

```
INFO [src/relay_server.rs:453] New relay request 8d62e9cd-... from [::ffff:1.2.3.4]:41563
INFO [src/relay_server.rs:437] Relayrequest 8d62e9cd-... from [::ffff:5.6.7.8]:53160 got paired
INFO [src/relay_server.rs:443] Both are raw
```

`New relay request` → `got paired` 这一对，说明两台机器握上了、正在走中继。
如果是直连成功，`hbbr` 反而**不会有**记录 —— 那更好，说明没走中继。

`hbbs` 的日志则是连接级别的，长这样：

```
DEBUG [src/rendezvous_server.rs:1135] Tcp connection from [::ffff:1.2.3.4]:38499, ws: false
```

## 排错清单

按顺序排，能解决九成问题：

1. **一直"正在连接"** → 九成是 `hbbs` 没写 `-r`，或者 21117 没放行。
2. **能连上但极慢、一直走中继** → 21116 的 **UDP** 没开，打洞失败。
3. **客户端连服务器都连不上** → 先 `telnet 你的IP 21116` 看看通不通；
   不通就是防火墙/安全组。**云厂商的安全组和机器自己的防火墙是两回事，都要看。**
4. **key 填错** → 表现是能连上服务器但握不上手。回头 `cat id_ed25519.pub` 核对一遍，
   注意别把 `.pub` 和私钥搞混，也别多复制空格。
5. **容器起来就退** → `docker logs hbbs` 看。极常见的是 `/opt/rustdesk` 权限不对。
6. **日志里啥都没有** → 确认客户端真的把 ID 服务器填成了你的地址，
   很多人填完忘了保存，或者填在"中继"那一栏了。

## 想要 TLS / 域名

默认这套是明文跑的。要加密有两个路子：

- **nginx / Caddy 反代 21118 和 21119**（这两个是 WebSocket 口），把
  `wss://` 转发过去，客户端里 ID 服务器填 `你的域名`，并打开"使用 TLS"。
- Caddy 更省事，它自动申请证书，配置就三行。

**这部分我没做** —— 我目前是 IP + 明文，因为就自己用。
上面写的是官方文档和社区里的通行做法，你自己上之前建议先拿一台测试机过一遍。

## 最后

搭完到现在跑了一阵子，中继日志里能看到自己的设备在互相配对，延迟比官方线路低不少。

如果你也打算自建，**建议跟 Tailscale 一起用**：RustDesk 负责"看屏幕"，
Tailscale 负责"让几台机器互相看得见"，我服务器上那些内部面板就都是只绑 tailnet IP 的。
那篇在这里：[把自己几台机器连成一张网](/posts/self-host-tailscale/)。
